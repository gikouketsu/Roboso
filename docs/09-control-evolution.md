# 09. STM32制御ロジックの変遷

3つのファームウェアは、完成度の異なる世代として保存しています。新しい版ほど高性能であることや、実機で採用されたことを意味しません。

## 比較

| 項目 | v1 | v2 | v3 |
|---|---|---|---|
| ファイル | `mbed_ball_tracking.cpp` | `mbed_ball_tracking_v2.cpp` | `mbed_ball_tracking_v3.cpp` |
| 日付記録 | 2024-10-17 | 2024-10-30 | 2024-11-06 |
| 入力 | SPI `x, y` | SPI `x, y` | SPI `x, y` |
| 不感帯 | 約±10 | 約±30 | 約±30 |
| 制御 | 固定dutyの閾値分岐 | PID形式 | PID形式 + 制限 |
| ゲイン | - | `Kp=.015`, `Ki=0`, `Kd=0` | `Kp=.015`, `Ki=.001`, `Kd=.005` |
| 出力制限 | 固定duty | `-1..1` | `-1..1`、変化幅 `0.05/cycle` |
| 積分ワインドアップ対策 | - | なし | 積分値 `-10..10` |
| x/y優先度 | 2つの独立した `if` 列 | x処理後にy処理 | `if / else if`でx優先 |
| 状態 | コードあり | コードあり、実質P制御 | **ファイル冒頭に「未テスト」** |

## v1: 閾値制御

`x < -10` で左旋回、`x > 10` で右旋回、`y` で前後進する最小構成です。ただし、左側判定と右側判定が別の `if / else if / else` 列になっています。例えば `x < -10` で `left()` を呼んだ直後、2つ目の列の `else` で `stop()` が呼ばれる可能性があります。

## v2: PID形式、実質P制御

v2は誤差、積分、微分の変数と式を持ちますが、`Ki=0`, `Kd=0` のため出力に寄与するのはP項だけです。そのため「PIDチューニング完了」や「PID制御を実機実証」とは表現しません。

v2もx方向の出力とy方向の出力を順に呼び出します。x偏差が不感帯外で旋回しようとしても、y偏差が不感帯内なら直後の `stop()` が旋回出力を上書きします。

## v3: 改良案、未テスト

v3では次のコードが追加されました。

- I項とD項
- 積分値の `-10..10` 制限
- 1ループあたりの出力変化を `0.05` に制限
- `if / else if` によるx方向の優先
- `int8_t` の範囲チェック

ただし、この版はソースファイル自体に「未テスト」と明記されています。さらに報告の考察でもPID調整は将来課題として扱われています。

## 全版にまたがる技術課題

### 1. `dt` と実時間の不一致

v2/v3は `dt=0.001` 秒を固定値として使いますが、制御計算はタイマ割り込みではなくSPI受信に応じて実行されます。実際の制御周期は計測されていないため、I/D項の数値に実時間的な根拠はありません。

### 2. `stop()` の意味の変化

v1/v2の `stop()` は6本のPWM出力に `1` を書き、v3は `0` を書きます。モータドライバの真理表と配線がない状態では、どちらがcoast、brake、または別の状態に対応するか判定できません。

### 3. コマンドウォッチドッグの欠如

新しいSPIデータが来ない場合にPWMを停止するタイムアウトはありません。最後の命令が残るリスクがあります。
